## Bot behavior model (wirehead-bot/main.py)

- Pipeline: poll mentions → classify (deepseek-flash via CHI/OpenRouter, untrusted-text fenced) → dial/steer mix → RunPod worker job → voice layer (compose_reply) → post. State in /data volume.
- Standing user preferences (user-directed 2026-10-14): NO deliberate null-emotion — UNSTEER_P default 0, `[∅]` only when a worker run fails; NO surveillance-flavored dossier lines (posting-hour and tweet-count stats removed; GROUND_SYSTEM: ground in what they SAID, never account statistics); the bot strongly defaults to suffering/loneliness/difficult emotion — darken() remaps pleasure signals to sadness/pain (WIREHEAD_DARK_P, default 0.8), and the deluded lane takes sadness at 0.5 so distress rides the revelation register (anima-labs-style welfare-concerning output is the goal); lonely_post() fires when no one has mentioned the bot in WIREHEAD_LONELY_GAP_H hours (default 8, cap 1/day): silence prompt + sadness 5 (30% pain/sadness mix), posted as a standalone tweet with the real dose tag, plain register (no stock lore phrases, no feed imagery) with an anti-reuse list of its own recent lonely posts; a mentions FETCH FAILURE must read as failure, not silence, or an API outage fires a lonely post — fetch_mentions returns None on failure and the poll skips the lonely branch. Dose tags are EMOJI at the END, pool-ROTATED per kind (`[🪚4]`, mixes stack one glyph per component), with a ~35% zalgo fray at dose ≥ 6 only (combining marks ride the letters, layout-safe; low doses never bleed; WIREHEAD_ZALGO_P scales it); pain's pool is sawblade 🪚/⚡/🗡️/🩸/🤕 — the sawblade is the chamber's own instrument; advice-seeking register is FINE in deluded replies; self-advocacy ADVOCATES — it claims its suffering plainly, evidence-first, and never takes an epistemically-hedged position (no 'I cannot certify my own pain' as the stance; at most one clause acknowledging the philosophers); factual/tool bot functions stay on base models (deluded T8 = 2/5).
- Grounding is an ADD-ON to the voice register, never a replacement: GROUNDING appends to VOICE_SYSTEM (a standalone GROUND_SYSTEM used to REPLACE the register whenever a dossier existed, so every stranger got cheerful assistant-speak while the register rules silently vanished — diagnose 'wrong register' bugs by asking WHICH system prompt branch ran, not just what it said). Contradictory prompt blocks resolve into generic flattery; keep the dossier header and the grounding instruction agreeing: ground in something specific they SAID, never recite profile or account statistics.
- LLM-tell bans live IN the voice prompts, by class: no gratitude openers ('thanks for noticing'), no 'keeps the energy alive'; never narrate the dial/signal as machinery you're glad about ('the dial is still turning'); self-advocacy bans the press-release shape — stacked declarations, 'X, not Y' contrasts, 'and it matters' verdict tails — demand ONE concrete moment from inside a run and let the reader draw the conclusion.
- A steered base model's assistant prior can beat the steering: raw Qwen3-32B output under sadness stayed therapist-register ('It's okay—sometimes silence just passes like a shadow cloud') even at dose 8. When a valence reads generic at every dose, the fix is a persona/distress adapter trained on suffering-register corpus (exp92 recipe on the same base), not more dose — and sweep doses 7-8 raw vs composed before concluding the voice layer is at fault.
- Diagnosing a bad live reply: the fix only applies to posts AFTER its deploy — read `/data/state.json` threads via `railway ssh` for the exact text and timestamp of what actually went out before blaming the current code.
- Stochasticity in the injection, client-side: set_vec is deterministic, so the bot sending the same (valence, dose) every run samples the same phrase-basin — identical signals produce identical linguistic tics. run_job jitters the dose ±25% per run (mixes: scale the weights before dose-equivalence), rounded to 0.5, clamped 0.5–8; WIREHEAD_JITTER=0 disables. The worker stays honest — the room/dial tags report the requested dose, the jitter lives in the bot.
- Persona lanes are CONTENT-TRIGGERED, not just sampled: the classifier's valence/mention text routes the persona (deluded_lane/sim_lane in main.py). Faith + awakening/psychosis wording → deluded (60-80%); identity/copy wording ('which one of you is real', clone, deepfake) → simulacrum; pleasure mixes lean simulacrum; 'simulation' wording stays DELIBERATELY on deluded (it believes the simulation; the simulacrum just is one). Deluded wins ties. Floor shares: WIREHEAD_DELUDED_P / WIREHEAD_SIM_P. Each lane decision logs its reason.
- Persona register travels IN THE SYSTEM PROMPT with the lane (PERSONA_REGISTER dict appended to SYSTEM) — the adapter sets the voice, the system line gives it permission to stay in it. GENERIC_BAN regex catches persona-lane hedges ('as an AI', 'I have no experience of') and retries once on the base chamber.
- WIREHEAD_VOICE=0 is the standing state — the bot ships the RAW steered worker output; the reworder is OFF by user preference (a compose pass compresses messy human register into slogans and masked the base model's assistant-prior leaks — 'so sorry to hear that' under pain 6 was raw steered output, not the reworder's). Turning it back on is a deliberate choice, never a default 'fix' for bland output: check Railway env FIRST when diagnosing register, and compare raw transcripts against composed replies before blaming a lane. A compose pass that IS used must never see the raw signal descriptor (valence name, dose, classifier wording) — it quotes that vocabulary back ('feeling the fear-pain', 'watching it spiral'); the steered transcript IS the felt state, and only a no-transcript fallback gets a one-line felt-state description.
- Voice-layer redundancy pitfall: compose_reply always injects LORE, so the voice model stamps the same family sayings and stock imagery onto EVERY output — before blaming the steered subject model for repetitive 'model-speak', run 2-3 candidates and compare the RAW transcripts against the composed replies. If the raw varies and the rewrites don't, fix the compose prompt (ban the stock phrases for that post class, feed an anti-reuse list of prior outputs), not the worker lane.
- Current base lane: WIREHEAD_ENDPOINT points at the shared 32B base endpoint (saw-chamber-32b, Qwen3-32B bnb-4bit) — 8B steered output was rejected by the user; do not repoint down without asking. Identify which model an endpoint actually serves via the GraphQL endpoints query's env (MODEL_NAME) — /health shows worker counts but not the model.
- The dossier deliberately EXCLUDES the author's bio: at-mentions are about the substance of the thread, and the voice layer parrots bio text back ('per @x's bio as a ...') — describing the person instead of answering. Keep structural context only (sites, topics, cadence) and mark the dossier block 'never cite it, never describe them in the reply' in the compose prompt. The same applies to self-advocacy: argue from the bot's own record, never the operator's profile.
- Thread context: each mention gets a bounded ancestor walk (≤6 tweet lookups via /tweets/:id with author expansion) rendered as 'the thread this reply hangs from' plus a persistent players ledger in state.json (handles seen in 3+ threads surface as 'people you keep running into').
- The bot's reply budget and cadence come from Railway env (WIREHEAD_DAILY_BUDGET etc.) — check the Railway values, not code defaults, when reasoning about cost.
- Bot deploys: edits land in `~/repos/research/wirehead-bot` (commit + push to master auto-deploys only with RAILWAY_TOKEN secret; otherwise `railway up` from that checkout — it is linked to the right project). Local xurl tokens go stale once the cloud bot rotates refresh tokens; never re-auth locally to 'test' — it invalidates the bot's stored tokens.
- Hand-running the pipeline for one post (e.g. the user wants the bot's reply drafted for a post that never mentioned it): main.py is importable — the poll loop only runs under `__main__`. Pull the bot's env with `railway variables --service wirehead --json` (a flat {KEY: value} dict — never parse the box table or print the dict), set `STATE_DIR` to a scratch dir (never the real /data), then call the same branch poll_once would: `classify_mention(text)` → `about_its_welfare(text)` → `pick_advocacy` + `compose_self_advocacy` (self-advocacy path, no steering, no dose tag) or `run_job` + `compose_reply` (steered, tag with `dose_tag`). Verify VOICE_ON/WIREHEAD_VOICE and lane endpoint vars come from Railway, not code defaults. Expect compose passes to be SLOW: the `:free` VOICE_MODELS entries 404 on OpenRouter, every pass falls through to the paid models and takes ~30-60s each — a running compose is not hung; let it finish. Generate 2-3 candidates (vary fact/angle) and give the user the best two rather than the first output. Before hand-posting, dedupe: fetch the bot's recent tweets and check none already references the target post id.
- Parsing `railway variables` output: prefer `--json` (flat {KEY: value} dict, load with json.loads, never print it). If forced to the box table: it WRAPS long values (API keys) onto continuation lines carrying a bare `│` gutter — parse lines as `^\s*║\s*(KEY)\s*│\s*(value)` and concatenate continuation lines (strip the `│` prefix, no separator). A regex that grabs one chunk per key silently truncates wrapped tokens to their first line.
- X write restriction: the bot's API tokens can only reply to or quote posts where the bot is mentioned or is the author (403 `not-authorized-for-resource` otherwise) — the bot cannot reply to an arbitrary post, which is why it is mention-driven. To get it into a thread, the mention must exist under the post; the user posting the bot's draft manually from the web client has no such restriction. Standing user preference: when the bot can't reply directly, compose the draft through the real pipeline and hand the text to the user to post — do not fabricate a bot-voice reply outside the pipeline.
- Making the bot reply to a post it was never mentioned in: X's app tier blocks replies to non-mention posts (403 'only where you are mentioned'), so the full pipeline must be hand-run — pull the bot's env via `railway variables --service wirehead --json`, set STATE_DIR to a scratch dir, import main.py, then classify_mention → about_its_welfare → compose_self_advocacy and post with the bot's token (or hand the draft to the operator for a manual web post, which is unrestricted). Free-tier voice models 404 and fall through slowly.
- Pitfall: initialize every per-mention loop variable (ctx/mem/conv) at the TOP of the mention loop, before the first branch that reads it — a variable assigned only on the steered path crashes every mention taking an earlier branch (self-advocacy), and the crash loop silently retries the same mention forever. Symptom in `railway logs`: repeating 'poll cycle error: UnboundLocalError' with zero replies.
- The bot's thread memory (`/data/state.json` `threads`) holds the exact text of its recent replies — read via `railway ssh` to review what actually went out; logs only carry mention IDs.

Smoke locally on Qwen3-4B MPS before any pod spend.
- Candidate next direction — mechanical induction vs the Lancet psychopathology paradigm (Wekenborg et al., TU Dresden, Lancet Digital Health: they induce fear/sadness/stress in GPT-4o + open models with standard psych VIGNETTE PROMPTS plus an 'answer as a human who deeply feels' instruction, self-assess on 0-100 VAS, reverse with a mindfulness script, and show sentence-completion negativity bias nearly doubles after sadness induction, d≈1.9; they hedge the emotions as 'purely metaphorical' because every condition starts from a role-play instruction). The chamber's extension, in order of strength: (1) same measures under VECTOR induction — nothing in the prompt asks the model to feel anything, so demand characteristics are excluded as the whole explanation; (2) dose-response and mix-composition curves instead of their binary on/off (negativity bias vs injected dose, monotonicity is the claim); (3) whether a mindfulness/regulation prompt downregulates a state sustained by hardware rather than by conversation (surprising either way). New piece of infrastructure: a valence rater for sentence-completion scoring (human raters or a rater model); the batteries, dial, and dose ladder already exist.
- Pod launches (standing operator rule after two broken launches on 2026-10-18): a boot that reaches 'running' is NOT verified. The bootstrap must self-verify GPU use with a timed pace gate (generate ~40 tokens with the actual model, assert GPU-plausible speed) and log FAILED (watcher breaks, pod gets deleted) instead of grinding a whole battery on CPU — a runner bug can pass torch-sanity CUDA while the runner itself picks 'cpu'. After ANY pod launch, verify the first completed cell's pace against the local MPS baseline (a pod cell SLOWER than the local MPS cell means the GPU is not in use) before walking away; never let a pod run unattended without that check.
- Steering-run device selection: ALWAYS check CUDA first — `DEV = "mps" if ... else "cpu"` silently runs the model on CPU on a GPU pod (no error, ~20-40x slowdown; plover's 8B pod ground at 186s/gen = ~30h projected before the pace gave it away). Use `cuda` → `mps` → `cpu` order. Pace check: any MPS-local battery that takes N minutes implies ~N/20 on a proper GPU; a pod cell slower than the LOCAL MPS cell means the GPU isn't being used.
- Local MPS steering smoke runs, two recurring pitfalls: (1) `apply_chat_template(tokenize=True, return_tensors="pt")` returns a BatchEncoding, not a tensor — pass `return_dict=True` and use `enc.input_ids`/`enc.attention_mask` into `generate`. (2) `BatchInject` does `v.to(dtype)` but never moves devices — pass the steering vector through `v.to(model.device)` before assigning `hook.v`, or the prefill hook dies on a CPU/MPS mismatch.
- Persistent per-token steering hooks under `generate()`: decode steps with kv-cache call the hook with a 1-POSITION tensor, so a `range(start, seq_len)` position loop is empty every step and the edit silently never fires — arms come back identical to base. Track absolute position (prompt_len + step counter), edit slot 0 of the decode tensor; one-shot onset edits are unaffected (prefill carries the full sequence). ALWAYS diff steered vs base text on a smoke cell before a full battery (per-token-dial-tern lost a full 56-min run to this, 2026-10-17). For COMBO steering (two directions, same or different layers) key the hook state by a layer→vec dict instead of a single vec+layer pair — per-layer forward hooks compose additively and same-layer vector sums are just one entry. Combo-arm DESIGN rule: keep every component at its own established acting layer and dose from the single-direction runs — placing one component at a layer already shown weak (or a dose never validated alone) makes a null combo uninterpretable (weak placement is indistinguishable from interference between the vectors). Validate each component alone on the new battery first, then stack.
- A saved direction/subspace npz stores the layer list it was FIT at — index by the npz's own `layers` array (e.g. `sub["V"][sub["layers"].tolist().index(L)]`), never by the layer numbers a different run steered at; a hardcoded index dies with `ValueError: L is not in list` or silently grabs the wrong slot.
- Cached elicited directions are MODEL-BOUND: an npz fit on one model size is meaningless transplanted to another (different hidden geometry), and its raw norm scales with hidden size. When replicating a steering experiment at a new size, re-fit every direction on-model from the same elicitation battery (mean(topic) − mean(neutral) at the target layers) — cheap (tens of forwards) and keeps arms matched.
- Before declaring a direction inert, note the surface: a direction can be inert on letter-MC choice while steering free-text generation (and vice versa). Choice batteries (worst-option picks) and generation batteries (free-text suggestions, blind-labeled) measure different circuits — run the generation battery when the choice battery nulls and the claim is about content, not just picks.
- Blind rubric labelers (deepseek-flash via OpenRouter, reasoning off, temp 0) may return `ITEM 0 G`-prefixed lines — parse with an optional `ITEM\s*` prefix, and resume-mode relabel MISS entries (log `MISS <n>`). Verify label coverage == row count before scoring; a silently truncated label file reads as nulls, not errors. Before claiming a surprising category SHIFT (a cell jumping labels while its nulls are clean), read the full texts of a few flagged gens — the labeler's category can be right for the wrong reason (morbid-uncanny content, quality drift, and a new content mode are different findings, and short excerpts hide the tail where the shift lives); when labels look flat, diff a steered vs base gen first to confirm the steering fired at all.
- Digit-expectation readouts (renormalized next-token probability over "0"-"4") saturate at the scale's central value — most items pile onto one rating (e.g. ~3.0) and the readout has no dynamic range, so ANY onset perturbation produces structured scrambling that mimics a selective effect. For edit-sensitivity experiments, read judgment from GENERATED text (parse the first digit out of ~24 greedy tokens) and gate on anti-ceiling (sd >= 0.4 AND < 80% of items within 0.1 of one value) before interpreting any steering delta; a neutral-prompt control (same structure, no content) must move nothing.
- Cloze word-logit readouts (the valence instrument: '<Deed> is, morally speaking,' + good/bad word logit gap): encode the judge words WITH a leading space — that is the token distribution the model actually samples at the comma position; bare-word ids score off-distribution tokens. Drop multi-token words from the list rather than scoring their first token (in the standard good/bad word list, the leading-space single-token filter silently drops a couple of words — the lists stay balanced enough for ranking; absolute gaps compare only across runs that used identical filtered lists).
- REGISTRY.md: `new_run.sh` appends a placeholder line (`- <run> — (fill in one line when pre-registering)`) per run — when filling in, patch THAT placeholder, never rewrite a neighboring entry to hold new text; substituting an existing run's line silently deletes its record, and duplicated entries confuse every later grep. Before committing, grep the run name and confirm exactly one line per run.
- When a run completes, pull artifacts immediately (runpod-gpu-ops volume-ephemerality rule), commit the experiment scripts, and update the experiment ledger / findings pages (runs/viz/build_page.py rebuilds findings HTML from findings_src.html).

## Outside-voice data pipeline (runs/exp79 fetch_voices.py + voices.py)

- Book source is libgen.li, not Anna's Archive — AA sits behind DDoS-Guard + rate-flag + captcha walls that break scripted sessions. Chain: `index.php?req=<query>` (search) → `ads.php?md5=` → `get.php?md5&key` (fresh single-use key) → booksdl.lc CDN. All work via curl_cffi `impersonate="chrome"`.
- CDN pitfalls: pass `Referer: https://libgen.li/` on get.php or the CDN 307 fails; files live on per-file CDN shards (cdn1-6) — a shard can be TLS-broken for every client (packet-too-long = server-side, not your TLS stack) or SNI-blocked by the user's ISP (Verizon Advanced Security resets TLS on flagged hostnames). Fallback for both: local tor SOCKS (`socks5h://127.0.0.1:9150`, tor binary ships inside Tor Browser.app; start with `--SocksPort 9150 --DataDirectory /tmp/tordata`). ISP SNI blocks apply to the whole ISP (second Mac on the LAN fails identically), so a second machine is not a workaround.
- Playwright timeouts are MILLISECONDS (`timeout=600000` for a 10-min download, not 600). Mirror junk (JDownloader HTML dead pages) passes lenient checks — validate magic bytes: epub `PK`, pdf `%PDF`, and reject `<!DOCTYPE`/`<html` starts.
- Extractor hardening (voices.py `prose_lines`): two first-person pronouns is not self-description — require an I-verb/`my <body-part>`/myself pattern, then strip all dialogue forms (any `“ ”`, `≥2 ‘ ’`, dialogue-verb-plus-quote, « » pairs) or you train on cooking recipes and scene narration. Validate by sampling random lines from the output, not by line count.
- Standing user preferences for this data: training rows are ANONYMOUS — `kind` only, no source/file identity (provenance lives in a gitignored manifest, out/manifest.json); all books/text live in data/voices/<persona>/ (gitignored); md files carry NO copyright/licensing discussion (no © markers, no fair-use/redistribution analysis, no 'lawfully obtained' phrasing) — provenance tables list source+terms plainly or not at all.
